## Requesting New Tools

Before requesting a new tool, check whether something in our existing stack already covers the need. Sprawl is expensive and creates security risk. If you've done that check and still think we need something new, follow this process.

<Steps>
  <Step title="Check the existing stack">
    Review this page and ask in `#help-it` or `#team-ops` whether a current tool can solve the problem. Many requests can be resolved with a feature or integration we already have.
  </Step>
  <Step title="Post in #tools-requests">
    Submit your request in `#tools-requests` with a clear description of the use case, how many people would use it, and why existing tools don't work. Include a link to the tool's pricing page if available.
  </Step>
  <Step title="Wait for Ops evaluation">
    The Ops team reviews all tool requests and responds within 3 business days. They'll evaluate cost, security, overlap with existing tools, and team fit.
  </Step>
  <Step title="IT provisions access if approved">
    If the request is approved, IT will handle procurement and provisioning. You'll get a confirmation in `#tools-requests` with next steps.
  </Step>
</Steps>

<Note>
  All tool access requests should go through IT. Don't share credentials or invite personal accounts to company tools.
</Note>
